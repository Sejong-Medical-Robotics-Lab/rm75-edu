**목표**

## 1. 원리 — 좌표는 어떻게 로봇의 것이 되는가

### 1-1. 변환 사슬

```
base_link ──(bringup TF)──▶ Link7 ──(T_ee_cam, 04)──▶ camera ──(YOLO+깊이)──▶ 물체
```

04에서 구한 `T_ee_cam`이 마지막 남은 조각이었다. 이제 사슬이 완성되어,
카메라가 본 어떤 점이든 base_link 좌표로 바꿀 수 있다.

### 1-2. 깊이는 '표면'을 잰다 — 반지름 보정

깊이 카메라가 주는 값은 **물체의 카메라를 향한 면**까지의 거리다.
파지 목표는 표면이 아니라 **중심축**이므로, 시선 방향으로 반지름만큼 밀어 넣어야 한다:

```
물체 폭(m) = bbox 폭(px) × 깊이 / fx
반지름     = 폭 / 2
중심점     = 표면점 + 반지름 × (카메라→물체 단위벡터)
```

실측 효과: 이 보정 없이는 보는 자세에 따라 좌표가 **16.0 mm** 흔들렸고,
보정 후 **8.2 mm**로 줄었다 (자세 8개 산포). 평균 x가 정확히 반지름만큼(24 mm) 이동한
것으로 보정이 옳게 동작함을 확인했다.

> 💡 이 보정은 **원통 근사**다. 각진 물병을 비스듬히 보면 실루엣이 대각선이 되어
> 반지름이 과대 추정된다(실측 27 mm vs 추정 32~34 mm). 수 mm 수준이라 파지에는
> 지장이 없었지만, 얇은 물체를 다룰 때는 유의할 것.

### 1-3. 높이(z)는 비전을 쓰지 않는다

bbox 중심의 z는 **뚜껑을 포함한 보이는 영역의 중간**이라, 시점에 따라 27 mm까지
달라졌다. 파지 높이로는 부적합하다. 이 문서에서는 **실측 파지 높이로 고정**한다
(`FIXED_Z = 0.083`, 아래 4절에서 자기 값을 만든다).

> 물체마다 높이가 다른 일반화(bbox 하단 기준 오프셋 등)는 06 이후의 과제다.

### 1-4. 파지 기하

```
물병 앞면 x   = 중심 x − 반지름
파지 Link7 x  = 앞면 x − GRASP_OFFSET(0.098)
접근 x        = 파지 x − 0.10
상승 z        = 파지 z + 0.05
자세          = (0, 0.707, 0, 0.707)   # 측면 파지, 그리퍼가 +x를 향함
```

`GRASP_OFFSET`은 "물병 앞면이 Link7에서 얼마나 앞에 오면 손가락이 감싸는가"의
실측값이다. 4절에서 직접 잰다.

## 2. A → B → C 검증 절차

### 2-A. 정적 검증 — 팔을 움직이기 전에

```bash
python3 vision_to_base_test_v3.py
```

영상 창의 상태 표시를 읽는 법:

| 표시 | 뜻 | 대응 |
|---|---|---|
| `NO DETECTION` (빨강) | 물병 미검출 | 시야·조명·거리 확인 |
| `MOVING` (주황) | 팔이 아직 움직이는 중 | 1초 기다림 |
| `TF STALE` (빨강) | TF가 오래됨 | bringup 터미널 확인 |
| `READY` (초록) | 측정 가능 | Enter로 기록 |

**두 가지를 확인한다:**

**① 일관성** — 팔을 4~6개의 크게 다른 자세로 옮기며(RViz Plan & Execute 이용)
같은 물병을 기록한다. 종료 시 산포가 나온다. **평균 오차 10 mm 안팎이면 통과.**
(실측: 8.2 mm)

**② 절대 정확도** — 로봇 자신을 자로 쓴다:
드래그 티칭으로 그리퍼 끝을 물병 앞면에 살짝 접촉 → `ros2 run tf2_ros tf2_echo base_link Link7`
→ `물병 중심 x = Link7 x + (플랜지→물병앞면 실측) + 반지름`.
이 값과 비전의 x를 비교한다. **10 mm 이내면 통과.** (실측: 4 mm)

> ⚠️ 접촉 실측에서 "Link7까지"의 기준점은 **팔 원통이 끝나고 그리퍼가 시작되는
> 플랜지 면**이다. URDF로 확인 가능: `tf2_echo Link7 4C2_baselink` → z = −0.009,
> 즉 그리퍼 베이스가 플랜지보다 9 mm 뒤. 기준점을 잘못 잡으면 수 cm씩 어긋난
> "가짜 오차"가 나온다 (검증 중 실제로 겪었다 — 53 mm 오차 소동의 원인이 이것이었다).

### 2-B. 접근 — 파지 없이 이동만

```bash
python3 vision_approach_test.py
```

READY에서 Enter → 계산된 목표(물병/앞면/파지/접근)가 출력 → **숫자를 눈으로 확인**
→ `go` 입력 시에만 발행된다. 범위(x 0.15~0.55 등)·이동량 검사에 걸리면 발행하지 않는다.

이동 후 확인:
- **y 정렬** — 위에서 봤을 때 그리퍼 중심선과 물병 중심이 맞는가
- **z** — 손가락이 몸통 높이에 왔는가
- **x** — 물병 앞면과 그리퍼 사이가 약 10 cm인가 (설계값)

**물병을 좌·중·우 세 위치에 놓고 반복**한다. 한 위치의 성공은 우연일 수 있다.

### 2-C. 파지 — 전체 시퀀스

```bash
python3 vision_grasp_test.py
```

READY에서 Enter를 누르는 순간 **좌표가 고정(latch)** 된다 — 이후 팔이 움직여
시야가 바뀌어도 재검출하지 않고 그 값으로 끝까지 간다. 이후 물병을 건드리지 말 것.

```
[1] MoveJ_P 접근      → 정렬 확인
[2] 그리퍼 개방        → 실제로 열렸는지 눈으로 확인 (아래 트러블슈팅 참고)
[3] MoveL 직진        → 물병이 손가락 사이로. 밀리면 즉시 q
[4] pick_on 파지      → 물렸는지 확인
[5] MoveL 5cm 상승    → 미끄러지지 않는지 확인
[6] (선택) 하강→개방→후퇴
```

각 단계는 Enter로 진행하고 언제든 `q`로 멈춘다. **좌·중·우 3회 완주가 목표다.**

## 3. 파라미터 레퍼런스

세 스크립트 상단의 상수 전부를 다룬다.
**굵은 글씨**가 환경(물체·테이블·캘리브레이션)이 바뀔 때 손대야 하는 값이다.
나머지는 특별한 이유가 없으면 그대로 둔다.

### 3-1. 파지 기하·그리퍼 (C 스크립트 중심)

| 파라미터 | 확정값 | 의미 | 언제·어떻게 바꾸나 |
|---|---|---|---|
| **`GRASP_OFFSET`** | 0.098 | 물병 앞면 → Link7 거리. 손가락이 물체를 감싸는 깊이를 결정 | **그리퍼·물체가 바뀌면** 4절 절차로 재실측. 작게 = 깊이 진입 (0.058 시도 → 0.098 유지로 확정) |
| **`FIXED_Z`** | 0.083 | 파지 높이 (base_link 기준, 고정값) | **테이블·물체 높이가 바뀌면** 4절 절차로 재실측 |
| **`GRIP_FORCE`** | 600 | pick_on 유지력 | 상승 중 미끄러지면 100씩 ↑, 물체가 찌그러지면 ↓ (400은 미끄러짐, 물 찬 병 기준 600) |
| `GRIP_SPEED` | 200 | 그리퍼 닫는 속도 | 그대로 (빠르면 물체를 쳐서 밀어냄) |
| `OPEN_POSITION` | 1000 | 개방량 (0=닫힘, 1000=최대) | 좁은 틈에서만 줄일 이유가 생김 |
| `APPROACH_BACK` | 0.10 | 파지 위치에서 뒤로 물러나 멈추는 거리 | 장애물이 많으면 ↑. 너무 크면 MoveL 직진 구간이 길어짐 |
| `LIFT_HEIGHT` | 0.05 | 파지 후 상승량 | 취향. 파지 확인이 목적이므로 크게 할 이유 없음 |
| `ORIENTATION` | (0, 0.707, 0, 0.707) | 측면 파지 자세 (그리퍼가 +x) | **파지 방향 자체를 바꿀 때만** (수직 파지 등 — 06 이후 과제) |
| `SPEED` | 10 | 팔 이동 속도 (%) | 올리지 않는다 (03 안전 수칙) |

### 3-2. 비전 (세 스크립트 공통)

| 파라미터 | 값 | 의미 | 언제·어떻게 바꾸나 |
|---|---|---|---|
| **`TARGET_CLASS`** | "bottle" | 잡을 COCO 클래스 이름 | **다른 물체를 잡을 때.** `cup`, `apple` 등 — 목록은 `python3 -c "from ultralytics import YOLO; print(YOLO('yolov8n.pt').names)"` |
| `CONF_THRESHOLD` | 0.5 | 검출 신뢰도 하한 | 검출이 자주 끊기면 0.3~0.4로 ↓, 오검출이 잡히면 ↑ |
| `ROI_RATIO` | 0.3 | bbox 중앙 몇 %를 깊이 ROI로 쓸지 | 얇은 물체(ROI가 배경을 물면) ↓, 표면 반사가 심하면 ↑ |
| `SMOOTH_WINDOW` | 7 | median smoothing 프레임 수 | 좌표가 떨리면 ↑ (반응은 느려짐) |
| `DEPTH_MIN/MAX` | 0.15 / 2.0 | 유효 깊이 범위 (m) | 작업 거리가 다르면 조정 — 배경 오인식 필터 역할 |
| `MAX_RADIUS` | 0.06 | 반지름 보정 상한 | 큰 물체를 잡을 때만 ↑ (검출 오류로 인한 과보정 방지용) |

### 3-3. 안전·TF (세 스크립트 공통)

| 파라미터 | 값 | 의미 | 언제·어떻게 바꾸나 |
|---|---|---|---|
| `X_RANGE` | 0.15~0.55 | 목표 허용 범위 (base_link) | **작업 영역이 다르면** 실제 테이블 범위에 맞춰 조정. 넓힐수록 오검출 좌표가 통과하기 쉬워짐 — 필요한 만큼만 |
| `Y_RANGE` | ±0.35 | 〃 | 〃 |
| `Z_RANGE` | −0.15~0.45 | 〃 | 〃 |
| `MAX_STEP` | 0.70 | 한 번에 허용하는 이동량 (m) | 그대로 권장. 검출 폭주를 거르는 최후 방어선 (0.35는 홈→접근 이동에 부족해 0.70으로 확정) |
| `MAX_TF_AGE` | 0.3 | 이보다 오래된 TF로는 변환하지 않음 (s) | 그대로. READY가 안 뜨면 값을 키우지 말고 TF 공급(bringup)을 고칠 것 |
| `STILL_THRESHOLD` | 0.002 | 팔 정지 판정 (m) | 그대로 |

### 3-4. 스크립트에 없는 값 — static TF

`T_ee_cam`(터미널2의 static TF)은 스크립트 상수가 아니라 **04의 산출물**이다.
카메라를 옮겼거나 재캘리브레이션했다면 04의 `make_tf_cmd.py`로 새 명령을 만들어
터미널2를 교체한다. **스크립트는 고칠 것이 없다** — TF만 바뀌면 된다.

### 튜닝 기록

> 💡 **미끄러짐의 원인은 깊이가 아니라 파지력이었다.** 처음에는 "얕게 물어서"라고
> 판단해 진입 깊이를 늘렸지만, 실제로는 force를 400 → 600으로 올리는 것으로 해결됐고
> 깊이는 원래 값이 맞았다. **한 번에 한 변수만** 바꿔 확인하는 03의 원칙이 여기서도
> 유효하다. 빈 병은 600에서 찌그러질 수 있다 — 그때는 500부터 시도.

## 4. 자기 환경의 값 만들기 — 실측 절차

물병·테이블·그리퍼가 바뀌면 아래 두 값은 다시 잰다.

**`GRASP_OFFSET`** —
① 드래그 티칭으로 그리퍼가 물병을 이상적으로 감싼 자세를 만든다
② `ros2 run tf2_ros tf2_echo base_link Link7` 로 Link7 x를 읽는다
③ 물병 앞면의 base_link x를 안다면(2-A ②의 접촉 실측):
   `GRASP_OFFSET = 물병 앞면 x − Link7 x`

**`FIXED_Z`** — 위 ②에서 함께 나온 Translation z가 그대로 파지 높이다.

두 값 모두 스크립트 상단 상수를 수정해 반영한다.

## 5. 트러블슈팅

| 증상 | 확인할 것 |
|---|---|
| `READY`가 안 뜸 (`MOVING` 지속) | 팔 정지 후 1초 대기 · bringup TF 정상인지 |
| `TF STALE` | 터미널1(bringup) 생존 여부 · `ros2 topic hz /joint_states` |
| base 좌표가 자세마다 크게 다름 | 터미널2 static TF에 **옛 캘리브레이션 값**이 들어갔는지 (04의 make_tf_cmd 참고) |
| 카메라 좌표는 고정인데 base만 흔들림 | TF 버퍼 지연 — 스크립트가 spin 스레드를 쓰는 최신본인지 확인 |
| 개방 명령 `True`인데 안 열림 | **툴 전원 재인가** (03 트러블슈팅의 그리퍼 복구 절차) |
| 상승 중 미끄러짐 | `GRIP_FORCE` ↑ (400 → 600 사례) · 파지 후 눈으로 확인하고 진행 |
| 3단계에서 물병이 밀림 | 즉시 q → `GRASP_OFFSET`이 너무 작지 않은지 · A 검증 재확인 |
| 검출은 되는데 좌표가 크게 틀림 | 다른 물체를 잡은 것 아닌지 (영상 창 박스 확인) · 반지름 `r=` 값이 상식적인지 |
| `[거부] 범위 밖` | 물병이 작업 범위 밖 — 옮기거나, 진짜 범위 확장이 필요하면 상수 수정 |
| 종료 시 Qt 타이머 경고 | 무시 — OpenCV 창을 스레드에서 닫으며 나는 것으로 동작 무관 |
| `rm_tf_publisher.py`가 연결 실패 | 05에서는 쓰지 않는다 (0절 참고 — bringup과 8080 충돌) |
