## 1. 왜 MoveIt인가 — 그리고 세 가지 설계 결정

05는 완주했지만 **경로가 아무것도 모른 채** 움직였다. 테이블도, 물병도, 그리퍼
자신의 부피도. 좌표가 정확했기에 사고가 없었을 뿐이다. 06은 그 "모름"을 없앤다.

### 결정 ① 그리퍼 제어는 rm_driver 토픽 그대로

MoveIt으로 그리퍼를 제어하지 **않는다**. 두 가지 이유다:

- **파지의 핵심은 힘 제어다.** 03·05에서 확인했듯 위치 제어로 닫으면 과부하 보호로
  힘이 풀려 이송 중 미끄러진다. MoveIt 그리퍼 그룹은 관절 각도 목표(위치 제어)라,
  성공시켜도 우리가 버린 방식으로 돌아가는 것이다.
- 실물 EG2-4C2에는 ros2_control 하드웨어 인터페이스가 없고, 개방도를
  `/joint_states`로 보고하지도 않는다 (03 참고).

### 결정 ② 그리퍼·카메라 형상은 '봉투(envelope)'로 부착

bringup 모델에는 그리퍼·카메라가 없다 → MoveIt은 그 부피의 충돌을 모른다.
02의 그리퍼 통합 모델(`rm_75_jaw_config`)로 bringup을 교체하는 대신,
**Link7에 그리퍼+카메라를 감싸는 박스를 `AttachedCollisionObject`로 부착**한다.

모델 교체를 안 하는 이유: 손가락 관절이 가동 관절인데 실물이 상태를 보고하지 않아
robot_state_publisher가 그리퍼 TF를 못 만들고 MoveIt 상태 모니터가 막힌다.
우회(가짜 joint_state, fixed 관절 URDF + 새 moveit_config)의 비용 대비,
봉투 부착은 코드 몇 줄로 같은 효과(충돌 검사에 부피 반영)를 낸다.
정밀 모델이 아니라 **실물보다 조금 큰 안전 봉투**라는 점만 기억할 것.

> 02의 jaw 모델이 버려지는 것은 아니다 — 시뮬레이션에서 그리퍼 포함 계획을
> 연습하는 제 역할이 있다. "실기에는 왜 안 쓰는가"가 이 절의 답이다.

### 결정 ③ 파지 순간의 모순은 'Scene에서 물병 제거'로 푼다

물병을 Scene에 넣으면 접근 경로가 물병을 피해 계획된다 — 좋다. 그런데 그 상태로는
**파지 자체가 '충돌'로 거부된다.** 그리퍼가 물병을 감싸야 하는데 플래너가 막는다.

해법: **접근까지는 물병을 Scene에 두고, 직선 진입 직전에 물병만 제거**한다.
테이블과 봉투는 끝까지 유지되므로 진입·상승 Cartesian도 테이블 충돌 검사를 받는다.
(대안인 `avoid_collisions=False`는 테이블 검사까지 꺼져서 채택하지 않았다.)

## 2. D → E → F 검증 절차

### 2-D. MoveIt 프리미티브 단독 — 비전 없이

```bash
python3 moveit_side_test.py
```

Scene 등록(테이블+봉투) → 측면 자세로 **계획→잔상 확인→실행** → +8cm 직선 전진
→ 후퇴. 각 단계에서 **RViz 잔상을 보고 Enter**를 누른다 — 03에서 배운
"잔상 확인 전 Execute 금지"가 코드로 강제된 구조다.

실측 확인 사항 (2026-08):
- bringup의 `/move_action`이 실물을 움직인다 (계획 소요 ~50 ms)
- 측면 파지 자세 `(0, 0.707, 0, 0.707)` 로 계획이 풀린다
- **Scene 박스가 떠 있어도 RViz는 생존한다** — 크래시는 '표시'가 아니라 '조작'에서 난다
- 직선 fraction 100%

> 💡 fraction = GetCartesianPath가 만든 직선의 완성 비율. 100%면 끝까지,
> 90% 미만이면 스크립트가 실행을 거부한다 — 중간에 충돌이 예측된다는 뜻이다.

### 2-E. 비전 + MoveIt — 전체 시퀀스

```bash
python3 vision_moveit_grasp_test.py
```

05의 C와 같은 latch·READY 게이트 구조에, 이동층만 MoveIt으로 바뀌었다:

```
[0] latch → 물병 실린더 Scene 등록 (RViz에서 실물 위치와 겹치는지 확인)
[1] MoveGroup 접근 — 물병을 '알고' 회피 계획 → 잔상 확인 → 실행
[2] 그리퍼 개방 (rm_driver)
[3] 물병 Scene 제거                     ← 결정 ③
[4] Cartesian 직선 진입 (테이블 검사 유지)
[5] pick_on 파지 (rm_driver)
[6] Cartesian 5cm 상승
[7] (선택) 하강 → 개방 → 후퇴
```

05와 눈으로 비교되는 차이:
- 접근 전에 **계획이 먼저** 나오고, RViz 잔상을 승인해야 움직인다
- 같은 목표를 여러 번 시도하면 **경로가 매번 다를 수 있다** (확률적 플래너)
- 물병 실린더가 RViz에 뜬다 — **검출 좌표의 시각화**이기도 하다.
  실물과 어긋나 보이면 비전부터 의심하라.

> 💡 시작 전에 그리퍼를 절반쯤 닫아 두면(`position: 500`) 2단계 개방이
> 실제로 동작했는지 눈으로 즉시 판정할 수 있다. "이미 열려 있어서 명령이
> 갔는지 알 수 없는" 상태를 만들지 않는 요령이다.

### 2-F. 가상 장애물 — 충돌 회피 실증

**06의 존재 이유를 한 장면으로 보여주는 실험.** 가상 패널이라 실물 없이 안전하다 —
팔이 빈 공중을 돌아가는 것 자체가 시연이 된다.

```bash
# 패널 등록 (별도 터미널, venv 불필요)
python3 add_obstacle.py add 0.30 0.20
# E를 다시 실행 → 접근 잔상이 패널을 피해 도는 것을 관찰
# 끝나면
python3 add_obstacle.py remove
```

실측 기록 (2026-08) — **패널 위치에 따라 세 가지 결말**이 나왔고, 셋 다 교훈이다:

| 패널 y | 결과 | 해석 |
|---|---|---|
| 0.12 (진입 회랑에 근접) | 접근은 패널을 감아 도는 자세로 성공 → **진입 fraction 14%로 거부** | MoveGroup은 우회할 수 있지만 **Cartesian은 정의상 직선뿐** — 우회 불가면 안 간다. 05의 MoveL이었다면 뚫고 지나갔을 상황 |
| 0.20 (회랑 확보) | 접근이 패널을 의식해 휘고, 진입 100% | **정상 데모 위치** |
| 물병 바로 앞 | 계획 자체가 실패 | "길이 없으면 안 간다" — 기본 모션에는 없던 성질 |

> 💡 y를 0.02씩 옮겨가며 "잔상은 휘는데 진입은 100%"인 경계를 찾아보라.
> 그 탐색이 Cartesian의 성격을 몸으로 이해하는 과정이다.
>
> `add 0.30 0.20 0.25` 처럼 세 번째 인자를 주면 **바닥 높이 z**가 지정되어
> 공중에 뜬 장애물(선반)이 된다 — 상하 회피 실험용.

## 3. 파라미터 레퍼런스

05의 비전·파지 기하 파라미터는 **전부 그대로**다 (05 문서 3절 참고).
06에서 새로 등장한 것만 다룬다. **굵은 글씨**가 환경 따라 재실측할 값.

### 3-1. Scene

| 파라미터 | 값 | 의미 | 언제·어떻게 바꾸나 |
|---|---|---|---|
| **`TABLE_Z`** | −0.010 | 테이블 면의 base_link z | **테이블이 바뀌면** 재측정. base_link 원점에서 **자로 직접** 잰다 (아래 4절 원칙) |
| `GRIPPER_BOX_SIZE` | (0.11, 0.13, **0.16**) | 그리퍼+카메라 봉투 크기 | 그리퍼·카메라가 바뀌면. **z(길이)를 실측 손끝 + 5mm로** — 0.19로 잡았더니 물병과 간격 8mm뿐이라 접근 계획이 확률적으로 실패했다 |
| `GRIPPER_BOX_CENTER` | (0, 0, 0.075) | 봉투 중심 (Link7 프레임) | 크기의 절반 (박스 원점은 중심) |
| `BOTTLE_HEIGHT` | 0.20 | Scene용 물병 실린더 높이 | 물체가 바뀌면 여유 있게 |
| `BOTTLE_RADIUS_MARGIN` | 0.005 | 검출 반지름에 더할 여유 | 키우면 안전하지만 접근 계획 난도 ↑ |

### 3-2. MoveIt

| 파라미터 | 값 | 의미 | 언제·어떻게 바꾸나 |
|---|---|---|---|
| `VEL_SCALE` / `ACC_SCALE` | 0.1 | 속도·가속 배율 | 올리지 않는다 (03 안전 수칙의 MoveIt판) |
| `allowed_planning_time` | 10.0 | 1회 계획 제한 시간 | 장애물이 복잡하면 ↑ |
| `num_planning_attempts` | 20 | 내부 재시작 횟수 | 〃 |
| (자동 재시도) | 3회 | 계획 실패 시 자동 재계획 | 확률적 플래너라 실패가 확률적으로 섞인다. **3회 모두 실패 = 구조적 문제**(도달 불가·Scene 간섭)로 판정 |
| fraction 하한 | 0.9 | 직선이 이 미만이면 실행 거부 | 낮추지 않는다 — 낮춘다는 건 "충돌 직전까지는 가겠다"는 뜻 |

### 3-3. 판정 완화 (실기 튜닝)

| 파라미터 | 값 | 튜닝 기록 |
|---|---|---|
| `STILL_THRESHOLD` | 0.005 | 05의 0.002에서 완화 — 검출 노이즈(±2~3mm)가 문턱을 넘나들며 팔이 멈춰 있는데도 MOVING↔READY가 널뛰었다. 파이프라인 정확도가 8mm이므로 5mm 문턱은 잃는 것이 없다 |

## 4. 실측 원칙 — 연쇄 측정보다 직접 측정

`TABLE_Z`를 정할 때 두 방법이 3 cm 어긋났던 실제 사례:

| 방법 | 값 | 문제 |
|---|---|---|
| 접촉 역산: Link7 z − "손끝 길이 15cm" | +0.021 | **손끝 길이는 개폐 상태에 따라 변한다** (열림 ~0.15 / 뻗음 ~0.18). 연쇄의 한 고리가 흔들리면 전체가 틀린다 |
| base_link 원점에서 자로 직접 | **−0.010** | 채택 |

원칙: **목표량을 직접 잰 값이 이긴다.** 기준점은 불변량으로 — Link7(플랜지 면)이나
base_link 원점. "손끝"처럼 상태에 따라 변하는 것은 기준으로 쓰지 않는다.
(05의 "53 mm 소동"과 같은 계열의 함정이다.)

## 5. 트러블슈팅

| 증상 | 확인할 것 |
|---|---|
| `[계획] ... 실패 (error_code=99999)` 후 자동 재시도 | 정상 — 확률적 플래너의 실패. **3회 모두 실패할 때만** 목표·Scene을 점검 |

| `AttributeError: ... no attribute 'error_code'` | 옛 스크립트다 — 액션 결과는 `get_result_async()` 래퍼의 `.result` 안에 있다. 최신본으로 교체 |
| 영상 창 `TF WAIT` 지속 | **터미널②(static TF)를 안 띄웠다** — E는 3터미널 구성 |
| Enter를 눌러도 무반응 | **OpenCV 영상 창에 포커스**가 가 있다 — `input()`은 터미널에서만 받는다. 터미널 클릭 후 입력 |
| 그리퍼 결과가 `None` (15초 침묵 후) | 그리퍼 전원 이상 — CLI로 `position: 500`을 직접 쏴서 실물이 움직이는지 판정 → 안 움직이면 **툴 전원 재인가** (03 트러블슈팅) |
| `[scene] 물병 제거 실패` (중단 직후) | 무해 — 중단 정리 루틴이 이미 없는 물병을 또 지우려던 것. RViz가 진실이다 |
| MOVING↔READY 널뛰기 | `STILL_THRESHOLD`가 0.005인 최신본인지 확인. 그래도 남으면 실제 진동(카메라·받침) 의심 |
| RViz 종료 | Scene 물체를 클릭했는지 — 표시만으로는 죽지 않음이 확인됨. launch 전체 재시작 |
| 종료 시 Qt 타이머 경고 | 무시 (OpenCV 창을 스레드에서 닫는 부수 현상) |

## 6. 산출물과 다음 단계

**기록해 둘 것:**
- F 실험 표 (패널 위치별 결과) — 자기 환경의 "진입 회랑" 폭
- 봉투 크기와 그 근거 (실측 손끝 길이)
- 05와의 비교 한 줄: 같은 파지인데 무엇이 달라졌나

**남은 한계 (07+ 후보):**
- 파지 후 물병이 Scene에 없다 — 들고 이동 중의 물병 충돌은 검사되지 않는다.
  `AttachedCollisionObject`로 파지 순간 물병을 그리퍼에 부착하면 해결된다 (봉투와 같은 기법).
- 높이(z)가 여전히 고정값 — 물체마다 다른 높이의 일반화.
- 접근 자세가 측면 파지 하나 — 물체·상황에 따른 자세 선택.
